# 0005 — Blog: Supabase-backed posts, edited from the WIMM admin

## Status

Accepted (phase 1: posts, editor, public pages). Phase 2 — comments,
likes/dislikes, view counts — is a separate change and will extend this ADR.

## Context

The site needs a blog whose posts are written and edited in an admin and
shown publicly at `/blog`. Each post shows its author (who created it), a
reviewer (who last edited it), and the date it was last updated.

An earlier draft put the editor in the staff admin as a new "Blog" app. That
was dropped: a blog is not an app with its own data, and the WIMM admin
already has the right audience.

## Decision

- **Where it's edited:** inside the WIMM admin, at `/wimm/admin/blog`, behind
  the existing Google sign-in and `money.promo_admins` membership
  (`requireWimmAdmin()`). The staff admin (`/admin`) is untouched, and the
  picker's "Where Is My Money?" card is the way in. Anyone in
  `promo_admins` can write and edit posts.
- **Storage:** a `blog_posts` table in the **main site** Supabase project (the
  same project that backs the WIMM admin), accessed only through
  `services/supabase/blog.ts` with the service-role key after
  `requireWimmAdmin()` has passed. RLS is enabled with no policies for
  anon/authenticated — the same pattern as `waitlist_signups` — so the
  table is unreachable except through server code. That code filters
  `status = 'published'` on every public read and never selects admin IDs.
- **Author and reviewer:** a post stores `author_id` / `reviewer_id` (the
  WIMM admin's user id, no foreign key) plus a display-name snapshot taken
  from the Google profile name (falling back to the part of the email before
  the `@`). The creator is the author. When someone other than the author
  edits a post they become the reviewer; the author editing their own post
  leaves the reviewer alone.
- **Format:** Markdown, rendered with `react-markdown` (the only new
  dependency). Raw HTML is not rendered and unsafe URL schemes are
  stripped. Images are not rendered in v1.
- **Rendering:** `/blog` and `/blog/[slug]` use ISR (`revalidate = 60`)
  plus `revalidatePath` when an admin saves, so edits appear immediately and
  public traffic doesn't hit the database on every request. Published posts
  are added to `sitemap.ts`.
- **`updated_at`** is set by the application on content edits, not by a
  database trigger, so the counters added in phase 2 don't change "last
  updated".

## Alternatives considered

1. **A "Blog" app in the staff admin** — needs staff `apps` changes and a
   display-name column in the admin-auth project; rejected as above.
2. **Markdown files in the repo** — no database, but every edit needs a
   deploy and can't be done from an admin.
3. **Public read policy (anon key) instead of service-role reads** — would
   expose `author_id`/`reviewer_id` unless column-restricted. Not worth the
   new surface.
4. **Plain text or a rich-text editor** — plain text is too limited; a
   rich-text editor adds several heavy client dependencies.

## Consequences

- One new dependency: `react-markdown`.
- One SQL file to run, in the main project: `docs/sql/blog.sql`. The
  admin-auth project is not involved.
- The blog editor shares the WIMM admin's look and its single access level:
  there is no separate "can write blog but not manage promo offers" role.
- Renaming an admin changes future posts only; existing posts keep the name
  that was current when they were written or last reviewed.
- Slugs are unique; changing a published post's slug changes its URL (no
  redirect is created).
